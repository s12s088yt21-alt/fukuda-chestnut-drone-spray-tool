# 栗園のドローン作業

既存の防除計算・散布チェック・設定保存・実績確認・請求資料を、一つの作業記録へ統合したローカル版。

## 起動

`作業記録を起動.command` をダブルクリック。Macでは http://127.0.0.1:8769/records.html を開く。
現在の公開ページへの反映は未実施。

## 画面の流れ

- 今日の作業。準備する → 作業する → 記録する。
- 過去の作業。保存履歴、2026年の機体ログ126タスク、バックアップ。
- 操作を調べる。2026年11月1日版の操作手順19章を検索。チェック項目から該当する手順へ移動。

薬剤・散布量・面積を一度入力すると、必要量、実績との比較、請求書に共用する。機体設定と実績は別の値で保存する。

## 保存

既存キー `kurien-flight-records-v1` とJSONバックアップ形式を継続。計算・請求条件は各記録の任意の `operation` に保存する。旧データはそのまま読める。
同じ端末・ブラウザ・URLで利用する。別端末との自動同期はない。バックアップは「過去の作業」で書き出す。
次回コピーでは日付を今日にして確認・実績をリセットし、計算条件を引き継ぐ。請求書番号・期限・個別申し送りはクリア。

## 構成

- `records.html` / `workflow.css` が統合画面。`index.html` はその入口。
- `records.js` / `records-core.js` が既存記録の保存、確認、コピー、バックアップ。
- `workflow.js` / `workflow-core.js` が計算、画面連携、履歴表示、請求書作成。
- `workflow-data.js` は既存の操作手順書と2026年DJIログから生成した参照データ。
- `serve.py` は127.0.0.1限定の静的サーバー。配信ファイルを許可リストで制限。

液剤の粉剤量kgを薬液量Lから差し引く計算はしない。粒剤kgと液剤Lを切り替える際に量を空へ戻す。薬剤の登録条件や推奨値は自動で決めず、ラベルと送信機で確認した値を入力する。

### 公開と私用データ

`workflow-data.js` は取得済み機体実績を含むローカル原本。Git対象外として保持。
`workflow-public-data.js` は機体実績と個別の本人報告を除いた操作資料。
`python3 build-public.py` で許可した16ファイルだけ `public-dist/` へ出力する。
公開先は既存GitHub Pagesの `gh-pages` ブランチ。mainを直接配信しない。
公開版には126タスクの私用ログを含めない。入力した作業記録はサーバーへ送信しない。

確認: `node --test records.test.cjs workflow.test.cjs mobile.test.cjs`
